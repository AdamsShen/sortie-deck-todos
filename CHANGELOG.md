# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- **API key revocation is a hard delete**: `DELETE /api/keys/{id}` now removes the row from `data/api_keys.sqlite` instead of writing `revoked_at`; clients using the key fail on their next request. `POST /api/keys` accepts `expires_in_months` and rejects anything outside 1/3/6/12. Existing rows are migrated with `expires_at = NULL` (treated as non-expiring) so an upgrade never invalidates keys in use

### Added

- **API key page (pass design)**: keys now live on a dedicated page at the same nav level as Decisions / Admin instead of a header modal. Each key is a time-boxed "agent pass": lifetime is chosen in calendar months (1 / 3 / 6 / 12, default 1), the stub shows the expiry date and days left, and an expired key is watermarked and rejected by `verify()` while staying visible for manual revocation. Issuing returns four client snippets (Claude Code `.mcp.json` + `claude mcp add`, Codex `~/.codex/config.toml`, Cursor `~/.cursor/mcp.json`, OpenCode `opencode.json`) alongside the one-time plaintext
- **Mission input snapshots (`missions/<id>/input/`)**: imported materials are no longer "an excerpt inside the mission JSON". Originals land in `input/files/<material_id>__<name>`, extracted text in `input/text/<material_id>.md`, and `input/manifest.json` is the single index (id / kind / mime / size / sha256 / pinned / extract status / relative paths). `mission_input.py` owns atomic writes (lock + `tmp`→`os.replace`), sha256 de-duplication, per-mission quota (50MB per file / 500MB per mission) and best-effort text extraction (pdf/docx/xlsx/text; missing dependency degrades to `extract_status=failed` without blocking the upload). `input/brief.md` becomes the canonical brief snapshot, `input_index_block()` gives prompts a path-only index so large files are read on demand instead of being inlined. `ExternalMaterial` gained `stored_path` / `text_path` / `sha256` / `extract_status` / `extract_error` / `origin`
- **Mission input API**: `POST/GET/PATCH/DELETE /api/missions/{id}/input` uploads originals as multipart (browser no longer sends only a text excerpt), pins/unpins and deletes them; the guard accepts the planning-session owner before the mission row exists and falls back to the usual run-control rule afterwards. The intake page uploads each picked file as soon as the briefing session hands back its pre-generated mission id, and chat-composer images are converted back from their data URL so they land in `input/files/` too
- **Dynamic input injection**: `StageContext.inputs` carries a path-only projection of `input/manifest.json`; `render_input_index()` renders an `## Input index` prompt section for both the harness executor and the Cursor coding executor, while `compose_brief()` inlines only excerpts up to 4000 chars and turns longer (or binary) pinned materials into "read `input/...` on demand" pointers
- **Knowledge pack audit trail**: `load_pack_for_cursor(mission_root=..., stage=...)` also archives the pack to `missions/<id>/logs/knowledge-pack/<stage>.md`, so the workspace copy can be recycled without losing "what did the agent know at that moment"
- **Orphan intake sweep**: `maintenance.sweep_orphan_missions()` recycles `missions/<id>` directories that have a planner session but no mission row after `TDT_INTAKE_TTL_DAYS` (default 7, measured from the newest `planner.*` file, skipping anything with `workspace/repos` content); wired into the hourly sweep + startup, and `sortie doctor` reports how many are pending
- **Structured role personas (prompt engineering)**: `persona.py` defines a six-section persona spec (role / background / skills / workflow / examples / constraints); built-in `packages/templates/personas/*.md` rewritten as "10-year senior expert" prompts; `PublishedAgent.persona_spec` / `ForgedAgentDraft.persona_spec` keep the structured view while `persona` stays the only runtime prompt (compiled via `render_persona`); Agent Forge now asks the LLM for the same structure and self-checks seniority / skills / examples / constraints; the workshop and forge review UI gained a structured editor with per-section enhancement (`scene=persona_section`)
- **OpenTelemetry full-chain tracing**: `observability.py` is the single contact surface (business code never imports `opentelemetry.sdk`). Emits a `mission.run` → `stage.run` → `gen_ai.chat` / `execute_tool` / `retrieval.recall` / `process.exec` span tree with GenAI semantic-convention attributes (model, input/output tokens, tool name) plus `sortie.*` business fields; exports OTLP/HTTP so Jaeger, Tempo, Grafana or Datadog all work unchanged. W3C `traceparent` rides inside the run-queue payload so `TDT_RUN_BACKEND=sqlite` workers stay on one trace; `TimelineEvent.trace_id` links a business event straight to its trace; log lines carry `trace=`. Off by default (`TDT_OTEL_ENABLED` + `TDT_OTEL_ENDPOINT`), and a no-op when the `[otel]` extra is not installed
- **Agent harness capability (system-wide)**: pluggable harness providers — `claude_code` (claude-agent-sdk), `opencode` (serve + HTTP), `codex` (headless JSON protocol), `cursor` (cursor-agent headless), `mock` (fallback) — all running cloud-side via SDK/protocol, never the user's local machine (`harness_providers/`). Selected per mission at creation, locked on `/start` (`Initiative.harness` / `harness_locked`, `TDT_DEFAULT_HARNESS=claude_code`); every stage conversation routes through the generic `HarnessStageExecutor` (legacy mock/coding executors remain as degraded fallback, `TDT_HARNESS_FALLBACK`); mid-run switch requires the HITL `switch_harness` action. Probe API `GET /api/harnesses` (TTL-cached), draft-time `PATCH /api/initiatives/{id}/harness`
- **Mission-bound memory**: `mission_memory.py` — per-initiative files under `data/missions/<id>/memory/` (`memory.md` rolling summary, `sessions/*.jsonl` multi-session transcripts, `context/*.md` bound files like brief/plan/harness). New sessions auto-load memory + bound files (`bootstrap_context`), token budget `TDT_MISSION_CONTEXT_TOKEN_LIMIT` triggers LLM auto-summary written back to `memory.md`
- **mem0 shared-memory backend**: `TDT_MEMORY_BACKEND=mem0` (`TDT_MEM0_BASE_URL` / `TDT_MEM0_API_KEY` / `TDT_MEM0_USER_PREFIX`) runs alongside the local `MemoryStore` (`CompositeMemory`), initiative-scoped isolation, hits merged into context blocks; RAG (`knowledge_gateway`) results are injected into harness context packs
- Workbench: harness selector with probe status on draft missions, locked-harness badge, HITL "switch harness" approval action
- **Tech design stage**: `eng_tech_design` (standard/default tracks, after PRD, before build) produces a reviewable `tech_design.md` (approach / module breakdown / risks / rollout-rollback), validated by the stage contract and gated by HITL; mock fallback `mock_tech_design`; harness missions route it through the same `harness_stage` executor
- **Mission-scoped RAG namespace**: stage key artifacts auto-indexed per initiative (`KnowledgeGateway.index_mission_artifact`, tags `ini:<id>`, WeKnora folder `missions/<id>`, idempotent + best-effort); `retrieve(query, initiative_id=...)` ranks the mission namespace first and fills from the global pool; harness context packs retrieve with mission scope (`TDT_KB_MISSION_INDEX` switch)
- **Mission-page sub-rooms**: the task view embeds its mission's sub-rooms — turn-by-turn live transcript, read-only member roster (opener / lead / participants, no editing) and a fullscreen conversation view; `SubRoomService.on_event` (wired through the orchestrator) pushes `subroom` / `subroom_message` onto the initiative SSE stream, so the panel needs no polling

### Fixed

- **Brief existed twice and drifted**: `memory/context/brief.md` was written once at start while `Initiative.brief` kept changing with materials, so a new session could bootstrap an outdated brief. `input/brief.md` is now the only snapshot and is rebuilt on every material change; the `memory/context` copy is gone
- **Empty Cursor runs counted as success**: `_count_impl_files()` included the injected `.cursor/rules` and `.sortie-deck` knowledge-pack files, so `wrote > 0` was always true and the "exit=0 but no implementation files" guard never fired. Both directories are now skipped
- **Mission ownership leak**: missions created by the briefing harness or `sortie smoke` had no `created_by`, and the visibility rule treated owner-less rows as visible to every account — a member could list, open, run and even delete another user's mission. Briefing sessions now carry `owner_id` (`start(owner_id=...)` / `handle(user_id=...)`) and stamp it when the mission is created; the CLI resolves an owner (`--owner`, default first admin); owner-less rows are admin-only, with `shared_with` still granting explicit access. `scripts/backfill_mission_owner.py` backfills historical rows (`--dry-run`, `--share-with`)
- **Codex provider**: probe accepts `$CODEX_HOME/auth.json` (no more false `auth_required`), parses the `item.completed` JSONL protocol (legacy format kept), runs with `stdin=DEVNULL` and `TDT_CODEX_SANDBOX` (default `workspace-write`), and maps credential failures to `needs_auth`
- **Orchestrator singleton**: an explicitly constructed `Orchestrator` now becomes the active instance, so graph-level sub-room / escalation hosts resolve the mission instead of a lazily created default instance (CLI and embedded runs)
- **QA gate loop**: approving a `qa_verify` gate without a declared verdict no longer bounces back to build forever
- **HITL resume race**: in-flight runs re-saved a stale initiative snapshot and wiped `pending_decision_id`, so an answered escalation left the mission paused; each stream step now refreshes from the store and `submit_hitl` waits for the run lock before resuming
- **Codex item-level errors**: configuration warnings emitted as `item.type=error` no longer fail an otherwise successful turn (only stream-level errors do)
- **Stage timeout reported as missing artifacts**: a stage cancelled by `TDT_STAGE_TIMEOUT_SECONDS` returned an empty artifact map, so the contract check raised `Stage ... missing artifacts` and hid the real cause. A failed stage now salvages contract files already written into its workspace (skipping `repos/` and empty files) and continues; when files are still missing, `StageContractError` carries the offending stage plus the executor failure (`timed out after ...`), and the failure event is attributed to the stage that actually failed instead of its parallel neighbour
- **Non-`Exception` crash during cleanup**: `cleanup_repos` / `cleanup_workspace` only caught `OSError`, but sandboxed runtimes (IDE bulk-delete guards) can raise `SystemExit` from `shutil.rmtree` — a `BaseException` that escaped the stage, LangGraph and ASGI, killing the API process and leaving the mission stuck in `running` (where `/start` is a no-op). Both helpers now also swallow `SystemExit` (re-raising `CancelledError`), and `_run_until_interrupt_inner` marks the mission `failed` with an error timeline event for any non-`Exception` exit signal instead of re-raising it

- **Process-wide run lock**: `Orchestrator._lock` wrapped the whole `graph.astream`, so a single process could only run one mission at a time — the queue, the workbench and any MCP/CLI front end all funnelled into a serial pipeline. Locks are now per initiative (same mission still mutually exclusive; different missions run concurrently)
- **Duplicate executions from a non-renewed lease**: `SqliteRunQueue.heartbeat()` was never called, so after `run_lease_seconds` (120s) another worker re-claimed a still-running job and re-ran the mission from its checkpoint; the worker loop now heartbeats every lease/3. `TDT_WORKER_ID` also defaulted to a constant `worker-1`, and `claim()` only respected a mission lock held by a *different* worker id, so two same-named replicas could run one mission twice — the id now derives `{hostname}-{pid}` when unset, and `claim()` honours any live lease regardless of worker identity
- **Lost mission updates with the JSON store**: `InitiativeStore` rewrote the whole `initiatives.json` per upsert with no locking, so concurrent missions clobbered each other's stage/artifacts/timeline. The runtime now uses SQLite only (row-level upsert + WAL); a leftover `TDT_STORAGE=json` fails fast at startup instead of silently degrading

- **Stage consult bypassed the LLM switch**: `stage_consult` / `manager` / `agent_forge` hard-coded `LlmClient(cli_fallback=True)`, so `TDT_LLM_CLI_FALLBACK=0` was ignored and every stage shelled out to `claude -p`; with no API key the CLI hung until its 60s timeout and the mission appeared stuck at `intake`. All call sites now respect the setting, the CLI fallback gets its own `TDT_LLM_CLI_TIMEOUT`, and the child process is killed when a mission is cancelled
- **Orphaned CLI processes**: cancelling a stage left the `claude` subprocess running; it is now killed on `CancelledError`
- **MCP tool errors were masked**: the SDK hides ordinary exception messages, so a bad mission id surfaced as `Error executing tool get_mission` with no detail — the model could not tell `not_found` from a server fault. Tools now raise `ToolError` carrying the stable `code: message` (`src/sortie_deck/mcp_server.py`)
- **Embedded `sortie mission start` lost its own run**: without `--wait` the CLI exited immediately and dropped the in-process run task, and `shutdown()` closed the SQLite connection while the task was still writing, so the mission landed in `failed` with a `Connection closed` traceback. Embedded mode now always waits for the first gate/terminal state (the process *is* the executor), and `_drain_tasks()` cancels leftover tasks before shutdown

### Changed

- **Briefing sessions are per-mission, no more global `briefings.json` (breaking)**: `BriefingStore` (one JSON file holding every session, rewritten in full on each turn) is replaced by `PlannerSessionStore`. A session now pre-generates its `ini_` mission id at `start()`, creates `missions/<id>/`, appends messages to `chat/planner.jsonl` and harness events to `chat/planner.events.jsonl` (append-only) and keeps small mutable state in `chat/planner.state.json` (tmp→`os.replace` + file lock). The mission is still created only on confirm, reusing that id, so `session_id == initiative_id` and there is nothing to migrate; concurrent users no longer clobber each other. Session auth before the mission exists uses `owner_id` from the state file (`403` for other users, admins included). On startup `data/briefings.json` is deleted outright (no migration, by decision) — historical briefing sessions are not resumable
- **Sub-rooms are owner-only**: `/api/subrooms`, `/api/subrooms/{id}/transcript` and the initiative SSE stream now require `initiative.created_by == current user` — shared users and admins who do not own the mission get `403` / receive no `subroom*` events, so an execution-time discussion never leaks wider than its mission owner. The workbench hides the in-mission 小群 drawer for non-owners, groups sub-rooms by owned mission behind a mission switcher, and no longer falls back to demo records when a mission has none
- Product rename: **Rally** → **Sortie Deck**; Python package `trusted-dev-teams` → `sortie-deck` (`sortie_deck`); CLI `sortie` (legacy `tdt` alias); legacy `rally_*` storage keys / `rally.executors` still accepted
- Orchestrator `startup()` recompiles confirmed custom graphs for HITL resume after restart
- Structured API error `pipeline_not_confirmed` when starting an unconfirmed mission
- **Routing is now conditional edges** rather than node `Command(goto=…)`: this LangGraph version still follows a node's static edges when it returns a `Command`, so both destinations would run in one superstep and collide on the shared state channels
- `RoleId` accepts unregistered role keys as first-class members; `AgentSlot` is no longer a closed union
- `compile_pipelines()` compiles every registered track by default; `list_tracks()` appends tracks beyond express/standard/default
- Executors gained an optional `run_session(ctx, host)` entry point; `run()`-only executors are unaffected
- **Collaboration capabilities are enabled by default** (`subroom_enabled`, `loadout_auto`, `mcp_call_enabled`, `skill_run_enabled`, `im_escalation`); each degrades safely when its dependency is missing, and setting it to `false` disables it
- **Harness context cost**: stage prompts now carry upstream artifacts as *summary + absolute path* (`artifact_summary.py`, LLM summary with rule fallback, cached per path + content hash) instead of full text, so the agent reads on demand; `StageContext.upstream_paths` is the new path map while `upstream_artifacts` keeps its full-text contract. Revert with `TDT_PROMPT_ARTIFACT_BRIEFS=false`
- **On-demand MCP mounting**: `harness_providers/mcp_binding.py` mounts only the MCP servers bound to the stage (binding + proactive recall + `toolkit_pick`) and passes `strict_mcp_config`, so the global `~/.claude.json` mcpServers no longer inject their schemas every turn; the claude coding CLI gets `--mcp-config` + `--strict-mcp-config`. Revert with `TDT_HARNESS_MCP_STRICT=false`
- **In-session auto-compaction**: `claude_code` injects `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (default 200000, `TDT_HARNESS_AUTO_COMPACT_WINDOW`) and coding CLI subprocesses inherit it; `compact_boundary` events plus `num_turns` / `usage` / `cost_usd` are reported in `StageResult.meta["context"]`. Optional `TDT_HARNESS_MAX_TURNS` caps non-converging stages
- **Agent switching is a graph node jump and the only routing mechanism**: there are no static edges between stages any more — every node announces its next hop in `handoff_target` and a conditional edge consumes it, with the frozen plan as the router's default. Agent hand-offs, manager join decisions and HITL verdicts all travel through that one router; the legacy `TDT_AGENT_HANDOFF` / `TDT_MANAGER_JOIN_DECISION` switches were removed
- **LLM access layer moved to LangChain ChatModel**: `LlmClient` now routes through `langchain_openai.ChatOpenAI` (`llm_chain.py`); the old hand-written httpx path was deleted outright (no runtime switch). `chat_json` / `chat_text` signatures, `backend` values (`http` / `claude_cli` / `none`) and the `claude -p` fallback are unchanged, so all call sites and existing tests are untouched. Endpoints that reject `response_format` retry once without it
- **Briefing waterfall is now a LangGraph subgraph**: the five-step plan waterfall (history → knowledge → pipeline → loadout → roles) moved out of `mission_briefing.py` into `harness/waterfall.py` as a fixed-edge `StateGraph`. Event order, `data.step` values and tool arguments are unchanged, and a failing tool still doesn't break the chain. No checkpointer — `PlannerSessionStore` remains the single source of truth
- `TDT_STAGE_TIMEOUT_SECONDS` default raised 900 → 1800: harness stages that produce a full tech design routinely need 15+ minutes, and the old cap cut them off just before the files landed
- **Admins are read-only on other people's missions**: run-control endpoints (start / stop / HITL / pipeline edit+confirm / harness / materials / room messages, joins and discuss toggles) now require `_ensure_mission_control` — owner or explicitly shared user — so a non-owner admin can follow a run but cannot steer it; sharing is creator-only (`_ensure_mission_share_owner`), while dissolve stays creator-or-admin (`_ensure_mission_delete`). Admins who own the mission or were explicitly shared keep full control; the workbench hides the gated controls and marks the room composer read-only for them
