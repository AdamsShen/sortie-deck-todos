## [Unreleased]

### Added

- **DSH sandbox auto-fallback (opt-in)**: `TDT_DSH_SANDBOX_AUTO_FALLBACK` (default `false`) probes the DSH sandbox backend once per process (cached with `TDT_DSH_SANDBOX_PROBE_TTL_SECONDS`) using an isolated `dsh_home/_probe` runtime and a fixed `echo` prompt — no task content, MCP or tool patches, and the probe home is deleted afterwards. When `tool/result` / reply text matches `SANDBOX_UNAVAILABLE`-style markers, that turn is relaunched with `danger-full-access`; probe errors or timeouts are conservative and keep `workspace-write`. Every fallback emits a `WARNING` with initiative/stage/session and `reply.meta.permission_fallback` / `probe_reason` / `effective_mode` / `probe_cached` (audit metadata survives the failure path too). Explicit task-level `full_access` skips probing. This is temporary mitigation for the cloud linux wheel missing a sandbox runner, **not** a safe default: without the outer per-run launcher it widens the permission surface in a shared `/data` container. It does not implement "approval-free commands inside the sandbox" — DSH `approval.policy='never'` means reject without asking, and workspace-local bash already needs no approval. See `docs/plans/2026-11-10-dsh-sandbox-auto-fallback.md` and `docs/*/modules/harness.md` §2.3
- **Claude Code Bash sandbox + cross-harness sandbox modes**: `docker/claude-sandbox.json` ships in the `runtime-harness` image and is activated by `TDT_HARNESS_SETTINGS_FILE`; sandboxed Bash runs without approval (`sandbox.autoAllowBashIfSandboxed`), writes are confined to the workspace, and `sandbox.credentials.envVars` masks API keys. `context_pack["sandbox"]["mode"]` provides harness-neutral `read_only` / `workspace_write` / `full_access`; `dsh` maps it to `DSH_PERMISSION_MODE`, `codex` to `--sandbox` plus `TDT_CODEX_ASK_FOR_APPROVAL` / `TDT_CODEX_NETWORK_ACCESS`. Dependency installs are prompt-constrained to `workspace/node_modules` / `.venv` and excluded from archive and review scope. `/api/health` reports the sandbox config and `bwrap`/`socat` availability
- **Bash sandbox prerequisites for the harness runtime**: the `runtime-harness` image now installs `bubblewrap` + `socat`, and the `worker` service gets `cap_add: [SYS_ADMIN]` plus `security_opt: [seccomp=unconfined, apparmor=unconfined]`. All three are required together on Ubuntu 24.04 hosts where `kernel.apparmor_restrict_unprivileged_userns=1`: default containers fail with `No permissions to create new namespace`, and any single relaxation still fails at uid-map or mount setup. Verified with throwaway containers; `api` keeps its original permissions. See `docs/plans/2026-11-10-claude-sandbox-替代bypass与任务级依赖.md`
- **DSH (DeepSeek Harness) as a built-in agent harness provider**: `dsh` joins the harness registry next to `claude_code`, driven by the official `deepseek-harness-sdk` (`harness-dsh` extra, pinned `0.2.1rc2`; the wheel ships its own runtime, so no system Node is needed). Capability parity with the Claude Code path: availability probe (`missing` / `auth_required` / `ok`), cross-process session resume (`resume_session(native_id)`), tool-level `stage_progress` activity, per-stage MCP mounting via generated `@deepseek-ai/dsh-mcp-client` patches, and `AUTH` errors mapped to the HITL auth block instead of a stage failure. Each turn spawns a throwaway runtime (`Session.run()` blocks and `close()` is never called by the executor) with a watchdog that kills it on timeout. Safe defaults ship as a static patch: session-log upload off (`session-log-deepseek`) and host skill roots cut (`skill-filesystem.includeDefaultRoots: false`). Known gaps documented in `docs/*/modules/harness.md`: one writable root per session (no `extra_dirs`), no max-turn knob, no token usage/cost, `Read` cannot be disabled alone, and `sse` MCP transports are skipped
- **IM integration layer (`src/sortie_deck/im/`)**: mission lifecycles can now be driven from enterprise IM. A provider-agnostic core (`base.py`) normalises inbound events and approval cards; `connection.py` stores one **workspace-scoped** connection per channel with Fernet-encrypted secrets (reusing the git-credential master key, never plaintext, never echoed back); `cards.py` renders one `ApprovalCard` into Feishu interactive cards, WeCom `template_card`, Slack Block Kit and DingTalk ActionCard; `router.py` dedupes by `(provider, raw_id)` and ACKs inside the platform window (Feishu 3s / DingTalk 1.5s / WeCom 5s) before running orchestration in a background task
- **Adapters**: `feishu.py` (tenant token + `card.action.trigger` + AES callback decryption), `dingtalk.py` (Stream frame parsing, `sampleActionCard{1..4}`), `wecom.py` (AI-bot WebSocket `aibot_subscribe` / `aibot_send_msg`, 30s heartbeat, single-connection constraint), `wechat.py` (iLink Bot: `get_bot_qrcode` / `get_qrcode_status` / `getupdates` / `sendmessage`, DM only, degrades cards to slash-command text)
- **Long-connection adapters (`im/streams.py`)**: Feishu (`lark-oapi` `ws.Client`) and DingTalk (`dingtalk-stream`) now actually connect. The SDKs' blocking loops run in daemon threads, events are marshalled back into the *same* payload shape the HTTP callbacks use (so one parser serves both transports), ACKs are returned immediately from the SDK thread, and `ImRunner` reconnects with the same backoff as WeCom. Both SDKs stay optional: without them the loop stops with an actionable `error` instead of silently pretending to be connected
- **Slack adapter (`slack.py`)**: Events API (`event_callback`) and Interactivity (`block_actions`) inbound — the latter is **form-encoded, not JSON**, so `/api/im/webhook/slack` branches on content type and verifies signatures against the raw body. Bot Token + Signing Secret are folded into encrypted JSON because the token itself is a credential (the `app_id` column stays empty); `bot_id` messages are dropped to avoid the bot triggering itself. Slack is URL-callback only — Socket Mode needs an app-level token the two-field form cannot hold
- **QR login (`qr_login.py`)**: WeChat scan-to-connect with a short-lived session, status polling (`wait` / `scaned` / `confirmed` / `expired` / `need_verifycode`) and token write-back that flips the connection to `connected`
- **Settings → IM integrations page**: channel cards with status badges, credential form with a mandatory "long connection vs URL callback" choice (the two are mutually exclusive **on the platform side**, so switching resets local state), probe/health readouts, WeChat QR panel with countdown, and chat→mission binding
- **Gate approvals as cards**: `Orchestrator._notify_gate()` now registers a pending decision (`notify=False`, so no duplicate notice) and sends an approval card carrying `decision_id` plus approve / rewrite / reject / stop buttons; failures degrade to the legacy text fan-out. Card actions map to real graph actions (`approve` is no longer treated as "edit instruction and rerun")
- **DingTalk signed action links**: DingTalk ActionCard buttons can only open a URL, so buttons point at `GET /api/im/action` with an HMAC-signature over `decision_id + action + timestamp` (TTL `TDT_IM_ACTION_TTL_SECONDS`, default 24h)
- **Tests**: `tests/test_im_{connection,cards,router,adapters,wechat,gate,api}.py` — 107 cases covering encryption/redaction, state machine, dedupe, ACK semantics, card rendering per platform, QR login, gate degradation and the full management API

### Fixed

- **Task-level permission overrides never reached the SDK harness, and environment failures looped forever**: `[sortie:coding_permission_mode=bypassPermissions]` injected after a HITL approval was only parsed by the legacy CLI executor; `claude_code` kept using the global `TDT_CODING_PERMISSION_MODE` (default `acceptEdits`), so every retry hit the same command-approval wall. On the 2026-11-09 snake mission this produced 8 build rounds + 4 QA rounds (~3h) with 36 blocked commands and no release. `permissions.py` now resolves the mode once for both paths and passes it through `context_pack` to `ClaudeAgentOptions`. A post-hoc classifier reads `selftest_log.json` / `test_report.json` (plus provider `permission_block` / `auth_block` markers) and tags `StageResult.failure_kind`; environment/auth blocks stop the run on the first occurrence instead of being routed back to `eng_implement`, and `TDT_MAX_CONSECUTIVE_SAME_FAILURE` (default 3) is a backstop for any other repeated failure. `TDT_PERMISSION_PREFLIGHT` warns at worker startup when interpreter commands cannot run; `/api/health` now reports the effective `permission_mode`. New tests: `test_permissions.py`, `test_env_block_pause.py`. Design and industry sources in `docs/plans/2026-11-09-权限阻断与环境阻塞熔断.md`
- **Long connections were a stub**: choosing "WebSocket long connection" for Feishu/DingTalk probed credentials over HTTP, reported `connected`, and never opened a socket — and `ImRunner.spawn`'s else-branch would have driven Feishu with the WeCom loop. Both channels now really connect (see `im/streams.py`), and `connecting → connected` is only promoted by the **first inbound event**, with `health.awaiting_first_event` distinguishing "waiting for traffic" from "subscription mismatch"
- **DingTalk inbound had no signature verification**: `/api/bridges/dingtalk` accepted any JSON on a public URL, so anyone could inject room messages. The unified `/api/im/webhook/{provider}` now verifies Feishu signatures/decryption and treats unverifiable payloads as 401
- **`/api/bridges/map` rejected DingTalk**: the allow-list only contained `slack`/`feishu`, so a DingTalk conversation could never be mapped — configuring it silently produced "conversation not mapped" forever
- **Inbound handlers ran orchestration inline**: resuming a pipeline inside the callback blew every platform's ACK window. Handlers now parse, enqueue and return, with processing on a background task
- **IM routes were registered after the MCP catch-all mount**: `/api/im/*` was appended below `app.mount("/", build_mcp_app(...))`, so the mount matched first and every IM request returned a `text/plain` `Not Found` instead of JSON — including with a valid token. The block now sits before the mount, and `CLAUDE.md` records the constraint (a mount on `/` swallows everything registered after it)

### Changed

- **Commit policy is now stage-specific**: build stages (`eng_implement` / `eng_ios` / `eng_android` / `eng_web` / `eng_backend` / `eng_agent`, including QA rework rounds) must keep their changes in the working tree — `git commit` / `git push` are forbidden, because `diff.patch` and the self-review scope are captured with `git diff` and a commit silently empties both. Selftest and QA stages may commit once per fix (still never pushing; `git_publish` owns push + MR). The prompt section is injected by `clone_repos(allow_commit=...)` and the previous unconditional "commit freely" instruction is gone
- **Multi-lens self-review now runs on build stages only**: selftest stages (`*_selftest`) are script-driven (the injected `scripts/selftest_runner.sh` runs the whole suite once and writes `selftest_result.json`), so reviewing them again only re-read the runner plus a few result files — the actual code had already been reviewed at the end of the build stage. `stage_in_review_scope()` no longer matches `*_selftest`, and `TDT_REVIEW_LENS_STAGES` now defaults to `build` (writing `selftest` there is a no-op; `integrate` still requires an explicit opt-in). Saves three model round-trips per selftest stage
- **Removed the redundant "Repo → credential preview" table** from Settings → Git credentials: registering a repo already forces a same-host credential binding, so the table only restated that fact. The "Available repos" / "Needs attention" readouts stay — the latter still flags repos whose bound credential was disabled or expired
- **Test-case boundary + verification budget for QA**: QA may only execute cases defined in `test_cases.md`. Browser scenarios now carry `case_id` and the runner skips anything outside that file (reported under `scope.skipped_cases`, never gating); rework re-runs only the failing ids via `--cases`. A cross-process budget (`max_runs`, default 5, tracked in `.qa_runner_state.json`) stops the "one more scenario" loop: exceeding it exits 5, writes `qa_budget.json` and leaves the previous `qa_result.json` intact. Prompt side: QA-only rules forbid adding cases, and rework stages (upstream `test_report.json` present) are limited to the failing ids

- **Verification stages get their own timeout**: `qa_verify` / `*_verify` now resolve to `TDT_QA_STAGE_TIMEOUT_SECONDS` (default 1800s = 30 minutes) instead of sharing the global/document fallback, so the review budget can be tuned per project (e.g. 600s for a small suite) without touching other stages; build stages keep their 3600s

- **Degraded stages self-check before QA**: a stage that ends with `status=fail` while self-review produced no verdict (all lenses skipped/failed) now re-enters once with a self-check instruction (`TDT_STAGE_SELF_CHECK_ATTEMPTS`, default 1, 0 disables): complete the contract artifacts, align `diff.patch`, run the tests, tick the checklist. Deploy stages are never re-run. Previously the half-finished output went straight to QA, which burned a full round (~9 minutes on the 2026-11-05 snake mission) only to return `fail`
- **Gate button follows the QA verdict**: with `qa_passed=false` the HITL payload now carries `verdict` + `recommended_action` (reroute to `on_fail`, label "返工"), so the workbench renders **Rework** as the primary button with the reason attached instead of "approve" — approving used to bounce back to build anyway, which read as a no-op

- **Per-stage timeout budget**: each stage can now carry its own `timeout_seconds` in the stage spec (pipeline YAML / `PipelineStageSpec`, persisted through `normalize_specs` → `materialize_template`). Resolution order: stage spec → `TDT_ENG_STAGE_TIMEOUT_SECONDS` (default 3600s, applies to `ENG_BUILD_STAGES`: eng_implement / eng_ios / eng_android / eng_web / eng_backend / eng_agent) → `TDT_STAGE_TIMEOUT_SECONDS` (default 1800s). Build stages get one hour by default because coding agents routinely exceed 30 minutes writing modules and running self-tests; the old single 1800s cap killed in-progress work and failed the stage with missing artifacts
- **API key revocation is a hard delete**: `DELETE /api/keys/{id}` now removes the row from `data/api_keys.sqlite` instead of writing `revoked_at`; clients using the key fail on their next request. `POST /api/keys` accepts `expires_in_months` and rejects anything outside 1/3/6/12. Existing rows are migrated with `expires_at = NULL` (treated as non-expiring) so an upgrade never invalidates keys in use

### Added

- **Shadow repository for un-git missions**: missions with no bound repo (code written from scratch under `workspace/repos/<name>/`) now get a mission-level shadow git repo at `missions/<id>/.shadow.git`. `GIT_DIR` / `GIT_WORK_TREE` are injected into a single subprocess only (never `os.environ`, never the agent's shell), a baseline commit is taken right after `clone_repos`, and `_git_diff` gains it as its second source — a real unified diff instead of a filename list. `repos/*` directories that already contain `.git` are excluded via pathspec (rescanned on every capture, so a mid-stage `git init` cannot turn into a `Subproject commit` gitlink); `workspace` itself being a git root still takes the project-diff path untouched. On the 2026-11-05 snake mission this was the difference between `diff_lines=0` and 24 files of reviewable content: self-review had burned 970s reading files one by one (`cat -n`, ~61s per step) and timed out twice. Failures degrade to the old filename listing, and `TDT_SHADOW_GIT_ENABLED=false` restores the previous behaviour without a code change
- **Budgeted diff for review prompts**: `ReviewScope.diff_excerpt` carries a clipped diff into the lens prompt (60k chars total / 2000 lines per file, both configurable via `TDT_REVIEW_DIFF_MAX_CHARS` / `TDT_REVIEW_DIFF_MAX_FILE_LINES`); oversized files collapse to their header plus added/removed counts and a `def`/`class`/`function` symbol list, while the `diff.patch` artifact keeps the full text. When a diff is present the lens prompt now forbids reading files one by one (max 3 reads for call-chain context) — that is what turned 24 files into 16 minutes of `Read` calls. Review turns also honour `TDT_REVIEW_DISALLOWED_TOOLS` (default `Read,Bash,Grep,Glob`, empty disables): with the diff already in the prompt, per-lens file reads were the remaining cost — the same lens measured 100.4s with Read available vs 39.0s with it disabled, so a 5-lens complex review lands around 3-4 minutes instead of 10.6
- **Scripted QA browser runner**: the QA stage now gets `scripts/qa_browser_runner.mjs` injected (project-owned copies are never overwritten). It starts the service from `qa.config.json`, polls the health URL, drives headless Chrome over CDP (scenarios support click / type / key / expect_visible / expect_hidden / expect_text / screenshot / wait_ms), writes `qa_result.json` plus `qa_screenshots/`, and tears the processes down — with no npm dependencies beyond Node's built-in WebSocket. The stage prompt forbids managing the server by hand or hand-writing CDP scripts (the 2026-11-05 snake mission spent 38 of 52 QA tool calls on Bash, rewriting its CDP script three times); a missing browser degrades to `browser_unavailable` so the model falls back to HTTP checks instead of inventing results

- **Scripted self-test runner**: selftest stages get `scripts/selftest_runner.sh` injected at stage start (a project-owned script with the same path is never overwritten). The runner starts the service from `selftest.config.json`, polls the health URL instead of `sleep`/`ps`, runs the whole suite once, writes `selftest_result.json`, and tears the process down via `trap EXIT`. The stage prompt now forbids manual start/stop and `pkill/kill/sleep/ps/lsof`, falling back to the old per-command checklist when the script is absent. Measured on the 2026-11-05 snake mission: 241 selftest tool calls, 99 of them environment management (27 starts / 22 pkill / 22 sleep / 28 ps). `selftest_result.json` joins the optional artifacts of every `*_selftest` stage
- **Stage metrics + duration insights**: every stage now writes one structured row to `data/metrics.sqlite` (`stage_metrics`: initiative / stage / role / harness / attempt / status / started_at / ended_at / duration_ms / tool_calls / review_rounds / review_verdict / meta) at teardown, covering serial, parallel and QA-retry paths. Writes are best-effort and can never fail a mission; tool calls count `phase=activity` progress events, review rounds come from `StageResult.meta.review`, and reruns increment `attempt` automatically. Settings → Data → Duration insights lists the missions you created with stage count / total time / tool calls / review rounds, and renders both a single-mission stage gantt and a multi-mission comparison (up to 5). APIs: `GET /api/insights/missions`, `GET /api/insights/missions/{id}`, `GET /api/insights/compare`; access is strictly owner-only (`created_by == user.id`) — admins are not exempt and shared missions are excluded
- **Office pipeline track + tier picker**: `office_pipeline.yaml` (`collect → produce → recommend`) gives everyday knowledge work neutral stage names, with `notes.md` / `report.md` / `recommendation.md` contracts; the legacy `research_*` stages stay runnable for existing missions and are folded into `office_*` by `enforce_tier`. `PATCH /api/briefing/sessions/{id}/prefs` stores the creation-page `task_kind` / `tier`, and the briefing commit now clamps its own draft proposal to the same budget instead of overwriting the tier plan. Workbench: the intake page gains task-type + tier chips with a live stage-chain preview fed by `GET /api/pipelines/tiers`
- **Pipeline tiers (express / standard / full)**: missions now declare `task_kind` (`delivery` / `knowledge`) and `tier`; `tiers.py` owns the per-tier stage whitelist, role ceiling and `enforce_tier()` — the planner may only **remove or collapse** stages inside the budget, never add. Collapsing maps specialised `eng_*` builds onto `eng_implement`, folds `<role>_selftest` into `eng_selftest`, drops per-role tech-design stages and cleans dangling `depends_on` edges. An explicit `pipeline_track` still wins (its YAML stage list becomes the budget). `GET /api/pipelines/tiers` feeds the creation UI and `/api/pipelines/suggest` accepts `task_kind` / `tier`. The same change registers the `research` track in the stage catalog (tagged `kind=knowledge`) and gives `research_scan` / `research_synthesize` / `research_recommend` their first artifact contracts (`notes.md` / `report.md` / `recommendation.md`)
- **Multi-lens self-review + implementation checklist**: coding/selftest stages now end with N review rounds (default 3: correctness → boundaries → test gaps; `>=5` adds concurrency and security) driven by the orchestrator on the same provider session — no host hooks, so claude_code / codex / cursor / opencode share one behaviour. Each round must answer with a ```review fenced block; the orchestrator records **what was reviewed** (changed files / contract artifacts / upstream / checklist items), **the result** (per-lens status, findings with severity, verdict), and **the status** (mode, harness, session, timings, errors, degradation) to `logs/<stage>/review.jsonl` + `review.json`, and archives `review.md` as an optional artifact surfaced through `StageResult.meta["review"]`. A `blocking` verdict becomes `needs_hitl` by default. Tech-design stages also emit an executable `checklist.md` (one item = one change + a verification command); build stages tick items off and record real `exit_code`s in `selftest_log.json`, while selftest stages may only re-run them. All artefacts are optional (`contracts.OPTIONAL`), switched by `TDT_REVIEW_LENSES_ENABLED` / `TDT_REVIEW_LENS_ROUNDS` / `TDT_REVIEW_LENS_STAGES` / `TDT_REVIEW_LENS_TIMEOUT_SECONDS` / `TDT_REVIEW_BLOCKING_POLICY`
- **API key page (pass design)**: keys now live on a dedicated page at the same nav level as Decisions / Admin instead of a header modal. Each key is a time-boxed "agent pass": lifetime is chosen in calendar months (1 / 3 / 6 / 12, default 1), the stub shows the expiry date and days left, and an expired key is watermarked and rejected by `verify()` while staying visible for manual revocation. Issuing returns four client snippets (Claude Code `.mcp.json` + `claude mcp add`, Codex `~/.codex/config.toml`, Cursor `~/.cursor/mcp.json`, OpenCode `opencode.json`) alongside the one-time plaintext
- **Mission input snapshots (`missions/<id>/input/`)**: imported materials are no longer "an excerpt inside the mission JSON". Originals land in `input/files/<material_id>__<name>`, extracted text in `input/text/<material_id>.md`, and `input/manifest.json` is the single index (id / kind / mime / size / sha256 / pinned / extract status / relative paths). `mission_input.py` owns atomic writes (lock + `tmp`→`os.replace`), sha256 de-duplication, per-mission quota (50MB per file / 500MB per mission) and best-effort text extraction (pdf/docx/xlsx/text; missing dependency degrades to `extract_status=failed` without blocking the upload). `input/brief.md` becomes the canonical brief snapshot, `input_index_block()` gives prompts a path-only index so large files are read on demand instead of being inlined. `ExternalMaterial` gained `stored_path` / `text_path` / `sha256` / `extract_status` / `extract_error` / `origin`
- **Mission input API**: `POST/GET/PATCH/DELETE /api/missions/{id}/input` uploads originals as multipart (browser no longer sends only a text excerpt), pins/unpins and deletes them; the guard accepts the planning-session owner before the mission row exists and falls back to the usual run-control rule afterwards. The intake page uploads each picked file as soon as the briefing session hands back its pre-generated mission id, and chat-composer images are converted back from their data URL so they land in `input/files/` too
- **Dynamic input injection**: `StageContext.inputs` carries a path-only projection of `input/manifest.json`; `render_input_index()` renders an `## Input index` prompt section for both the harness executor and the Cursor coding executor, while `compose_brief()` inlines only excerpts up to 4000 chars and turns longer (or binary) pinned materials into "read `input/...` on demand" pointers
- **Knowledge pack audit trail**: `load_pack_for_cursor(mission_root=..., stage=...)` also archives the pack to `missions/<id>/logs/knowledge-pack/<stage>.md`, so the workspace copy can be recycled without losing "what did the agent know at that moment"
- **Orphan intake sweep**: `maintenance.sweep_orphan_missions()` recycles `missions/<id>` directories that have a planner session but no mission row after `TDT_INTAKE_TTL_DAYS` (default 7, measured from the newest `planner.*` file, skipping anything with `workspace/repos` content); wired into the hourly sweep + startup, and `sortie doctor` reports how many are pending

Emits a `mission.run` → `stage.run` → `gen_ai.chat` / `execute_tool` / `retrieval.recall` / `process.exec` span tree with GenAI semantic-convention attributes (model, input/output tokens, tool name) plus `sortie.*` business fields; exports OTLP/HTTP so Jaeger, Tempo, Grafana or Datadog all work unchanged. - **Duplicate artifact entries from parallel stages**: wave merges keep both the bare contract key (`tech_design.md`) and the stage-scoped copy (`eng_backend_tech_design::tech_design.md`) in `upstream`, and both can point at the same path (the branch that won last-wins). `Orchestrator._sync_artifacts_from_upstream` snapshotted existing paths once before the loop and never updated it, so the second key appended the same path again and the stage inspect panel listed the same file twice. ### Fixed

- **Brief existed twice and drifted**: `memory/context/brief.md` was written once at start while `Initiative.brief` kept changing with materials, so a new session could bootstrap an outdated brief. `input/brief.md` is now the only snapshot and is rebuilt on every material change; the `memory/context` copy is gone
- **Empty Cursor runs counted as success**: `_count_impl_files()` included the injected `.cursor/rules` and `.sortie-deck` knowledge-pack files, so `wrote > 0` was always true and the "exit=0 but no implementation files" guard never fired. Both directories are now skipped
- **Mission ownership leak**: missions created by the briefing harness or `sortie smoke` had no `created_by`, and the visibility rule treated owner-less rows as visible to every account — a member could list, open, run and even delete another user's mission. Briefing sessions now carry `owner_id` (`start(owner_id=...)` / `handle(user_id=...)`) and stamp it when the mission is created; the CLI resolves an owner (`--owner`, default first admin); owner-less rows are admin-only, with `shared_with` still granting explicit access. `scripts/backfill_mission_owner.py` backfills historical rows (`--dry-run`, `--share-with`)
- **Codex provider**: probe accepts `$CODEX_HOME/auth.json` (no more false `auth_required`), parses the `item.completed` JSONL protocol (legacy format kept), runs with `stdin=DEVNULL` and `TDT_CODEX_SANDBOX` (default `workspace-write`), and maps credential failures to `needs_auth`
- **Orchestrator singleton**: an explicitly constructed `Orchestrator` now becomes the active instance, so graph-level sub-room / escalation hosts resolve the mission instead of a lazily created default instance (CLI and embedded runs)
- **QA gate loop**: approving a `qa_verify` gate without a declared verdict no longer bounces back to build forever
- **HITL resume race**: in-flight runs re-saved a stale initiative snapshot and wiped `pending_decision_id`, so an answered escalation left the mission paused; each stream step now refreshes from the store and `submit_hitl` waits for the run lock before resuming
- **Codex item-level errors**: configuration warnings emitted as `item.type=error` no longer fail an otherwise successful turn (only stream-level errors do)
- **Stage timeout reported as missing artifacts**: a stage cancelled by `TDT_STAGE_TIMEOUT_SECONDS` returned an empty artifact map, so the contract check raised `Stage ... missing artifacts` and hid the real cause. A failed stage now salvages contract files already written into its workspace (skipping `repos/` and empty files) and continues; when files are still missing, `StageContractError` carries the offending stage plus the executor failure (`timed out after ...`), and the failure event is attributed to the stage that actually failed instead of its parallel neighbour
- **Non-`Exception` crash during cleanup**: `cleanup_repos` / `cleanup_workspace` only caught `OSError`, but sandboxed runtimes (IDE bulk-delete guards) can raise `SystemExit` from `shutil.rmtree` — a `BaseException` that escaped the stage, LangGraph and ASGI, killing the API process and leaving the mission stuck in `running` (where `/start` is a no-op). Both helpers now also swallow `SystemExit` (re-raising `CancelledError`), and `_run_until_interrupt_inner` marks the mission `failed` with an error timeline event for any non-`Exception` exit signal instead of re-raising it

- **Process-wide run lock**: `Orchestrator._lock` wrapped the whole `graph.astream`, so a single process could only run one mission at a time — the queue, the workbench and any MCP/CLI front end all funnelled into a serial pipeline. Locks are now per initiative (same mission still mutually exclusive; different missions run concurrently)
- **Duplicate executions from a non-renewed lease**: `SqliteRunQueue.heartbeat()` was never called, so after `run_lease_seconds` (120s) another worker re-claimed a still-running job and re-ran the mission from its checkpoint; the worker loop now heartbeats every lease/3. `TDT_WORKER_ID` also defaulted to a constant `worker-1`, and `claim()` only respected a mission lock held by a *different* worker id, so two same-named replicas could run one mission twice — the id now derives `{hostname}-{pid}` when unset, and `claim()` honours any live lease regardless of worker identity
- **Lost mission updates with the JSON store**: `InitiativeStore` rewrote the whole `initiatives.json` per upsert with no locking, so concurrent missions clobbered each other's stage/artifacts/timeline. The runtime now uses SQLite only (row-level upsert + WAL); a leftover `TDT_STORAGE=json` fails fast at startup instead of silently degrading

- **Stage consult bypassed the LLM switch**: `stage_consult` / `manager` / `agent_forge` hard-coded `LlmClient(cli_fallback=True)`, so `TDT_LLM_CLI_FALLBACK=0` was ignored and every stage shelled out to `claude -p`; with no API key the CLI hung until its 60s timeout and the mission appeared stuck at `intake`. All call sites now respect the setting, the CLI fallback gets its own `TDT_LLM_CLI_TIMEOUT`, and the child process is killed when a mission is cancelled
- **Orphaned CLI processes**: cancelling a stage left the `claude` subprocess running; it is now killed on `CancelledError`
- **Web approvals were credited to the wrong channel**: the `/hitl` route built `HitlDecision` without a `source`, which defaults to `web`, so an approval submitted by the CLI was audited as "approve via 网页" (and `meta.last_hitl_by` lost the real channel). `HitlSubmitRequest` now carries `source` (default `web` for older clients), the route forwards it to both `submit_hitl` and `stop`, and the CLI sends `source="cli"`
- **Artifact paths only worked with the full store key**: `read_artifact` / `GET .../artifacts/{path}` / `sortie mission artifacts --cat` all required the exact key shown by the listing, so the natural `stage/file` or bare `file.md` returned 404. Path resolution now lives in `service.artifact_candidates()` and is shared by REST, MCP and CLI (bare filenames resolve when unique, otherwise `conflict` lists the candidates)
- **MCP tool errors were masked**: the SDK hides ordinary exception messages, so a bad mission id surfaced as `Error executing tool get_mission` with no detail — the model could not tell `not_found` from a server fault. Tools now raise `ToolError` carrying the stable `code: message` (`src/sortie_deck/mcp_server.py`)
- **Embedded `sortie mission start` lost its own run**: without `--wait` the CLI exited immediately and dropped the in-process run task, and `shutdown()` closed the SQLite connection while the task was still writing, so the mission landed in `failed` with a `Connection closed` traceback. Embedded mode now always waits for the first gate/terminal state (the process *is* the executor), and `_drain_tasks()` cancels leftover tasks before shutdown

### Changed

- **Briefing sessions are per-mission, no more global `briefings.json` (breaking)**: `BriefingStore` (one JSON file holding every session, rewritten in full on each turn) is replaced by `PlannerSessionStore`. A session now pre-generates its `ini_` mission id at `start()`, creates `missions/<id>/`, appends messages to `chat/planner.jsonl` and harness events to `chat/planner.events.jsonl` (append-only) and keeps small mutable state in `chat/planner.state.json` (tmp→`os.replace` + file lock). The workbench hides the in-mission 小群 drawer for non-owners, groups sub-rooms by owned mission behind a mission switcher, and no longer falls back to demo records when a mission has none

Revert with `TDT_PROMPT_ARTIFACT_BRIEFS=false`
- **On-demand MCP mounting**: `harness_providers/mcp_binding.py` mounts only the MCP servers bound to the stage (binding + proactive recall + `toolkit_pick`) and passes `strict_mcp_config`, so the global `~/.claude.json` mcpServers no longer inject their schemas every turn; the claude coding CLI gets `--mcp-config` + `--strict-mcp-config`. Revert with `TDT_HARNESS_MCP_STRICT=false`
- **In-session auto-compaction**: `claude_code` injects `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (default 200000, `TDT_HARNESS_AUTO_COMPACT_WINDOW`) and coding CLI subprocesses inherit it; `compact_boundary` events plus `num_turns` / `usage` / `cost_usd` are reported in `StageResult.meta["context"]`. Optional `TDT_HARNESS_MAX_TURNS` caps non-converging stages
- **Agent switching is a graph node jump and the only routing mechanism**: there are no static edges between stages any more — every node announces its next hop in `handoff_target` and a conditional edge consumes it, with the frozen plan as the router's default. Agent hand-offs, manager join decisions and HITL verdicts all travel through that one router; the legacy `TDT_AGENT_HANDOFF` / `TDT_MANAGER_JOIN_DECISION` switches were removed
- **LLM access layer moved to LangChain ChatModel**: `LlmClient` now routes through `langchain_openai.ChatOpenAI` (`llm_chain.py`); the old hand-written httpx path was deleted outright (no runtime switch). `chat_json` / `chat_text` signatures, `backend` values (`http` / `claude_cli` / `none`) and the `claude -p` fallback are unchanged, so all call sites and existing tests are untouched. Endpoints that reject `response_format` retry once without it
- **Briefing waterfall is now a LangGraph subgraph**: the five-step plan waterfall (history → knowledge → pipeline → loadout → roles) moved out of `mission_briefing.py` into `harness/waterfall.py` as a fixed-edge `StateGraph`. Event order, `data.step` values and tool arguments are unchanged, and a failing tool still doesn't break the chain. No checkpointer — `PlannerSessionStore` remains the single source of truth
- `TDT_STAGE_TIMEOUT_SECONDS` default raised 900 → 1800: harness stages that produce a full tech design routinely need 15+ minutes, and the old cap cut them off just before the files landed
- **Admins are read-only on other people's missions**: run-control endpoints (start / stop / HITL / pipeline edit+confirm / harness / materials / room messages, joins and discuss toggles) now require `_ensure_mission_control` — owner or explicitly shared user — so a non-owner admin can follow a run but cannot steer it; sharing is creator-only (`_ensure_mission_share_owner`), while dissolve stays creator-or-admin (`_ensure_mission_delete`). Admins who own the mission or were explicitly shared keep full control; the workbench hides the gated controls and marks the room composer read-only for them
