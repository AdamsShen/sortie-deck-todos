## 一、总览

提示词不是「一个阶段一个模板文件」，而是每次调用 provider 前由 `HarnessStageExecutor._build_prompt()` **运行时拼装**，按 `"\n\n"` 连接成一份纯文本：

```
persona（角色定义）
  + 任务约束（只做本阶段 / 不要问用户）
  + Stage / Role / 输出位置
  + Human instruction + Mission brief
  + intake 专属产出规格（仅 intake）
  + 上游产物摘要（路径指向 .upstream 镜像）
  + 滚动记忆 / 绑定文件 / 输入索引 / RAG / 分层记忆 / 工具 brief
  + 元工具协议 / 记忆工具协议 / 小群协议
  + 清单协议（技术方案 / 编码阶段）
  + 控制平面协议（handoff / escalate）
  + QA 结论协议（QA 阶段）
  + 仓库段 / 产物索引
  + 边界硬限制（Scope guard）
  + ## Result 收尾要求
```

兜底是内置 persona 文件（带 front-matter 契约，front-matter **不进**提示词）：

- 目录：`packages/templates/personas/<role>.md`（product / design / eng / eng_web / qa / deploy …）
- 加载：`templates.py:43-80`（`load_persona` / `load_persona_document`）

**修改指引**：要改某个角色的提示词风格，改 `data/agents.json` 里对应 agent 的 persona，或改模板 persona 文件；不要改 `executor.py`。

## 五、知识库 / 记忆 / 工具 / skill / MCP 怎么进提示词

### 5.1 两条通道

| 通道 | 含义 | 覆盖资源 |
|---|---|---|
| **入口静态注入** | 每阶段开始时拼进提示词，不检索 | persona、阶段规格、上游摘要、工具 brief、滚动记忆、绑定文件、RAG brief、MCP 列表 |
| **循环内按需检索** | 模型在回复里声明意图，编排层兑现后再回注 | 工具/skill 检索、记忆检索、小群讨论 |

### 5.2 知识库（RAG）

- 入口自动检索一次：query = `brief + stage`，`limit=6`，超时取 `harness_rag_timeout_seconds`（默认 5s，本项目 `.env` 设 15s）：

```1525:1562:/Library/git-root/sortie-deck-todos/src/sortie_deck/harness_providers/executor.py
    async def _rag_brief(self, ctx: StageContext) -> str:
        ...
        hits = await asyncio.wait_for(
            asyncio.to_thread(
                gateway.retrieve,
                f"{ctx.brief} {ctx.stage}",
                limit=6,
                initiative_id=ctx.initiative_id,
            ),
            timeout=limit,
        )
```

- 检索顺序：**任务命名空间（`ini:<id>`）优先 → 全局池**（`knowledge_gateway.py:308-358`）。
  - 任务命名空间：**本地关键词打分**（`_retrieve_mission`，`knowledge_gateway.py:406-430`），命中 ≥ limit 时全局池不参与；
  - 全局池：WeKnora `hybrid`（向量 + BM25 → RRF → rerank），`graph` 模式改走 knowledge-chat 图谱扩展，失败降级 hybrid。
- 产物回写知识库的白名单：`prd.md / tech_design.md / design.md / handoff.md / integrate.md`，`intake`、`done` 不索引（`orchestrator.py:674-676`）。

### 5.3 记忆（两层）

| 层 | 时机 | 内容 | 代码 |
|---|---|---|---|
| 分层记忆 brief | 入口注入 | 四层作用域（workspace / user / mission / agent）合并 + 相关度 + 新近度，最多 12 条简介行 | `memory.py:540-588`、`orchestrator.py:113-148` |
| 滚动记忆 + 绑定文件 | 入口注入 | `memory.md` 摘要 + 绑定文件全文（截断 6000 字符） | `mission_memory.py:205-236` |
| 记忆检索 | 按需 | `memory_search` / `memory_read`，读预算 4 次 / 单条 2000 字符 | `graph.py:488-547` |

记忆检索在 `memory_retrieval=weknora` 时优先语义召回：召回 id → 回映射本地条目 → **可见性以本地 buckets 为准** → 不足用本地打分补足（`memory.py:590-625`）。

### 5.4 工具 / skill（两层）

| 层 | 时机 | 内容 | 代码 |
|---|---|---|---|
| 计划期装配 | 航线启动时 | 按角色/阶段的 capability 选条目，渲染成 `toolkit_brief` | `orchestrator.py:863-885`、`loadout.py:336+` |
| 阶段主动召回 | 每阶段入口 | query = 角色+阶段+标签+brief，过阈值才注入（`loadout_stage_recall`） | `graph.py` 阶段召回段 |
| 循环内检索 | 按需 | `toolkit_search`（≤5 候选）→ `toolkit_pick`（≤8/阶段）→ `skill_run`（≤4/阶段） | `loadout.py:159-164`、`executor.py:79-98` |

召回打分：`weknora` 后端优先（混合检索 + rerank，经 `toolkit_index` 镜像），未配置 / 抛错 / 空召回 → 本地三层加权（capability 1.0 > tags 0.6 > 正文 0.25），见 `loadout.py:96-153`。

### 5.5 MCP

- 本阶段挂载哪些 MCP 由 `ctx.toolkit_ids` 决定：`_mcp_servers()` → `mcp_servers_from_toolkit`（`executor.py:1505-1523`）；
- `harness_mcp_strict=true` 时只挂这些，不再加载本机全局 `mcpServers`；
- **不能热挂载**：本阶段 `toolkit_pick` 的 MCP 从下一阶段才生效（协议里写死）。

### 5.6 上游产物

- 入口只给「摘要 + 路径」：
  - ≤ `prompt_inline_artifact_chars`（默认 1200）字符 → 直接内联全文；
  - 超长 → LLM 摘要（`prompt_artifact_summary_llm`，按内容 hash 缓存），失败回退首段截断；
- 路径指向 `.upstream/` 镜像（文档阶段在 `artifacts/<stage>/.upstream/`，编码阶段在 `workspace/.upstream/`），全文由 agent 按需 Read；
- 编码阶段镜像与遗留清理：`_mirror_upstream`（`executor.py:298-320`）/ `_sweep_stale_contracts`（`executor.py:340-374`）。

### 6.4 什么时候「服务正常也不走 WeKnora」

1. 召回为空（镜像异步解析未完成 / 查询不命中 / 库为空）→ 记忆、工具降级本地；
2. 异常 → 同上；知识库则直接空 brief；
3. 任务命名空间：永远是本地关键词；
4. KB id 未配置 → 强制降级 local；
5. `.env` 未加载：`env_file=".env"` 相对于**进程工作目录**，不是仓库根就会全部回落代码默认值（local）。

### 6.5 已知问题（待处理）

- **intake persona 冲突**：agent persona 的「约束」段写着「只写 prd.md 与 acceptance.json」，与 intake 新规格「只写 intake.md」相矛盾。实测模型服从后者，但建议后续给 intake 裁剪 persona 或加显式优先级。
- **上游 PRD 回退冗余**：无上游摘要时把 `ctx.brief` 当 PRD 再打一遍（`executor.py:1632-1634`），导致 brief 在提示词里出现两次。

## 七、协议块（声明-兑现）

真实 harness 的 agent loop 跑在 provider 进程里，编排层无法直接调用工具，所以统一用**回复文本里的 JSON 围栏块**声明意图：

| 协议 | 围栏 | 用途 | 兑现方 |
|---|---|---|---|
| 元工具 | ` ```toolkit_intent ` | `toolkit_search` / `toolkit_pick` / `skill_run` / `memory_search` / `memory_read` / `mcp_calls` | `graph.run_toolkit_meta` / `run_memory_meta` |
| 小群 | ` ```subroom ` | 拉一个临时讨论间拿结论，再回注本轮 | `executor._maybe_consult_subroom` |
| 控制平面 | ` ```control ` | `handoff`（交接给谁）/ `escalate`（升级真人） | `executor` 解析 + `graph._apply_handoff` |

协议块在兑现后会从正文剥离，不污染产物与记忆。

### 9.3 常见坑

1. **`.env` 不在 CWD**：所有 `TDT_*` 回落默认值（记忆/工具变本地）。
2. **任务库挤掉全局库**：任务命名空间命中 ≥ limit 时全局池不参与。
3. **MCP 不能热挂载**：本阶段 pick 的 MCP 下一阶段才生效。
4. **镜像延迟**：新建工具/记忆条目要等 WeKnora 解析完才能被召回，期间降级本地。
5. **intake 撞轮次**：保持 20 轮，靠 `_INTAKE_SPEC` 收敛；不要靠降轮次提速。
