# 工具白名单与工具箱优先级

> 适用代码基线：`dev` 分支（2026-11-16）
> 相关模块：`toolkit` / `orchestrator` / `graph` / `loadout` / `harness_providers`
> 关联文档：[`docs/zh/modules/agents.md`](zh/modules/agents.md)、[`docs/zh/modules/toolkit.md`](zh/modules/toolkit.md)、[`docs/zh/modules/executors.md`](zh/modules/executors.md)

## 1. 一句话结论

**绑定集做加法（高优先级覆盖低优先级），白名单做减法（不可突破），组织策略是公司级上限，`enabled` 是硬门槛。** 四层叠加后的最终 `toolkit_ids` 才会真正挂载 MCP、注入 skill 说明。

## 2. 参与决策的字段

| 字段 | 所属层 | 含义 |
|---|---|---|
| `ToolkitItem.enabled` | 工具箱 | 条目是否启用；未启用不挂载、不召回、不可 pick |
| `ToolkitItem.kind` | 工具箱 | `tool` / `mcp` / `skill`，决定后续走哪条链路 |
| `PublishedAgent.toolkit_ids` | 角色 | 角色的默认工具包（工坊发布时绑定） |
| `PublishedAgent.tools_allowed` | 角色 | 角色级工具白名单（工坊可配，P0 新增） |
| `AgentContract.tools_allowed` | 契约 | persona front-matter 声明的白名单，角色级为空时兜底 |
| `CreateInitiativeRequest.role_toolkits` | 任务 | 创建任务时按角色覆盖默认工具包 |
| `CreateInitiativeRequest.stage_toolkits` | 阶段 | 按阶段覆盖；优先级高于角色级 |
| `org_policy.allowed_toolkit_ids` | 组织 | 组织级允许列表，约束召回与 in-loop pick |
| `stage_disallowed_tools` | 阶段 | 禁用**内置工具名**（Bash/Read 等），与工具箱白名单正交 |

> 注意：`toolkit_ids` 是"默认绑定"，`tools_allowed` 是"允许上限"。前者可以被任务级覆盖放大，后者任何层都不能突破。

## 3. 四层优先级

### 第一层：绑定集（加法，高优先级覆盖低）

| 优先级 | 来源 | 行为 |
|---|---|---|
| 1（最高） | `stage_toolkits[stage]` | **替换**角色级绑定 |
| 2 | `role_toolkits[role]` | **替换**角色默认工具包 |
| 3 | `PublishedAgent.toolkit_ids` | 角色默认 |
| 4（追加） | 阶段主动召回 `recall_out.item_ids` | 并集追加，不替换 |
| 5（追加） | 阶段内 `toolkit_pick` 上浮 | 写回 `stage_toolkits`；MCP 下一阶段生效，skill 可本阶段执行 |

关键实现：

- 建队时的覆盖：`src/sortie_deck/orchestrator.py:951-956`
- 阶段节点的覆盖：`src/sortie_deck/graph.py:1891`（`stage_toolkits.get(stage) or role_toolkits.get(role.value)`）
- 召回追加：`src/sortie_deck/graph.py:1903-1906`

**注意**：`stage_toolkits or role_toolkits` 是 `or` 语义，**覆盖不是合并**。阶段级一旦配置，角色级整组失效。

### 第二层：`tools_allowed` 白名单（减法，不可突破）

取值优先级：

```text
PublishedAgent.tools_allowed（工坊配置，非空）
  → AgentContract.tools_allowed（persona front-matter，非空）
  → []（不限制，保持旧行为）
```

非空时与当前绑定集取交集，在四处执行：

| 执行点 | 位置 | 作用对象 |
|---|---|---|
| 建队 | `src/sortie_deck/orchestrator.py:957-964` | 角色默认绑定 + 任务级 `role_toolkits` |
| loadout | `src/sortie_deck/orchestrator.py:1032-1041` | `ini.meta` 里未过滤的任务级覆盖 |
| 阶段节点 | `src/sortie_deck/graph.py:1907-1919` | 阶段级绑定 + 主动召回 |
| 阶段内 pick | `src/sortie_deck/graph.py:2191-2194` | `toolkit_pick` / `skill_run` |

过滤函数是纯函数，便于单测：

```68:79:/Library/git-root/sortie-deck-todos/src/sortie_deck/models.py
def filter_toolkit_by_contract(
    toolkit_ids: list[str], tools_allowed: list[str]
) -> list[str]:
    """按角色契约的工具白名单过滤 toolkit id。

    白名单为空表示不限制（保持旧行为）；非空时只保留命中的条目，
    避免角色加载契约外的 MCP / skill。
    """
    if not tools_allowed:
        return list(toolkit_ids)
    allowed = {t.strip() for t in tools_allowed if t and t.strip()}
    return [t for t in toolkit_ids if t in allowed]
```

**白名单只做减法**：

- 不能复活已禁用或已删除的条目；
- 不会自动给角色添加工具；
- 白名单里的条目如果不在绑定集内，依然不会挂载。

### 第三层：组织策略（公司级上限）

`org_policy.allowed_toolkit_ids` 非空时，作为硬过滤传给：

- 主动召回：`src/sortie_deck/graph.py:1681-1720` → `run_stage_recall(..., allowed_ids=allowed)`
- 召回实现：`src/sortie_deck/loadout.py:148`（`allowed_ids` 不在集合内直接跳过）
- in-loop pick：`src/sortie_deck/loadout.py:227`（`item is outside the org allowlist`）
- 与角色白名单在 pick 路径取**交集**：`src/sortie_deck/graph.py:2191-2194`

**当前边界**：组织策略只约束"召回"和"pick"两条动态路径，**不约束显式绑定的 `toolkit_ids`**。因此实际包含关系是：

```text
组织策略（拦召回 / pick） ⊇ 角色白名单（拦绑定 / 召回 / pick） ⊇ 实际挂载集
```

### 第四层：启用与可用性（硬门槛）

| 检查 | 位置 | 效果 |
|---|---|---|
| `item.enabled = false` | `src/sortie_deck/loadout.py:144-145` | 不参与召回 |
| `item.enabled = false` | `src/sortie_deck/mcp_runtime.py:186` | 不进入 MCP 挂载列表 |
| `item.enabled = false` | `src/sortie_deck/orchestrator.py:994-995` | 不写入 `toolkit_brief` |
| 条目不存在 | `src/sortie_deck/loadout.py:221-224` | pick 拒绝并回传原因 |
| MCP 缺 `command` / `url` | `src/sortie_deck/harness_providers/mcp_binding.py:86-89` | 跳过并记 note |
| 探活失败 | `src/sortie_deck/loadout.py:229-233` | pick 拒绝，模型可换条目 |

## 5. 三个阶段的具体行为差异

| 阶段 | 白名单是否生效 | 说明 |
|---|---|---|
| 建队（`create_initiative`） | 是 | 用角色白名单收敛 `role_toolkits` 与 published 默认值 |
| 阶段启动（graph 节点） | 是 | 对「阶段绑定 + 召回结果」再过滤一次，防止越界 |
| 阶段运行中（in-loop pick） | 是（P0 后） | 与组织白名单取交集；MCP 本阶段不挂、下阶段生效 |
| 阶段运行中（`skill_run`） | 是 | 复用 `pick_candidate` 的校验链 |

## 6. 示例

### 场景一：任务级覆盖 + 白名单

```text
工具箱：A(mcp), B(skill), C(skill)

角色默认工具包 = [A, B]
任务级覆盖     = [B, C]      ← 替换角色默认，不是合并
角色白名单     = [A, C]
阶段召回       = [D]

绑定集 = [B, C] + [D] = [B, C, D]
白名单收敛 [A, C]     → [C]
最终挂载 = [C]
```

结果：`A` 被任务级覆盖丢掉，`B` 被白名单丢掉，`D` 被白名单丢掉。

### 场景二：阶段级覆盖

```text
角色绑定 = [A, B]
阶段绑定 = [C]

最终绑定 = [C]（阶段级整组替换）
```

### 场景三：白名单为空

```text
角色白名单 = []
绑定集 = [A, B, C]
最终挂载 = [A, B, C]
```

空列表表示"不限制"，与引入白名单之前的行为完全一致，用于保证存量角色零回归。

## 7. 排障顺序

某个工具没有生效时，按以下顺序排查：

1. **工具箱**：`enabled` 是否为 true；条目是否还存在。
2. **绑定集**：是否落在最终 `toolkit_ids` 里（注意 `stage > role > published` 的覆盖关系）。
3. **白名单**：角色工坊里的「工具白名单」是否把它排除；角色级为空时是否被 persona front-matter 兜底。
4. **组织策略**：召回或 pick 路径是否被 `org_policy.allowed_toolkit_ids` 挡住。
5. **类型链路**：
   - MCP：`transport` 是否缺 `command` / `url`；是否被 `strict_mcp_config` 过滤。
   - skill：是否先 `toolkit_pick` 再 `skill_run`；是否超出单阶段 4 次执行预算。
   - tool：是否只作为说明写入 `toolkit_brief`，需要模型经元工具调用。

## 8. 设计理由

- **绑定与白名单分离**：绑定解决"默认效率"，白名单解决"安全边界"。二者合一会导致任务级覆盖天然突破安全限制。
- **白名单放在角色层而非阶段层**：角色决定"这个岗位能碰什么"，阶段决定"这个步骤默认用什么"，职责不重叠。
- **组织策略只拦动态路径**：显式绑定被视为已审核配置，动态召回/pick 才是不可控入口，因此只对后者做硬过滤。
- **空值即不限制**：存量 `agents.json`、旧任务快照没有新字段，Pydantic 默认值填充后行为不变，保证零回归。
