## 1. 体系分层与作用域

三层记忆体系 + 可选共享后端：

| 层 | 实现 | 粒度 | 存储 |
|---|---|---|---|
| 条目记忆 | `memory.py` | 单条事实/偏好/战例/教训（4 作用域） | `data/memory.json` |
| 任务文件记忆 | `mission_memory.py` | 滚动总结 / 会话转录 / 绑定文件 | `missions/<id>/memory/` 明文文件 |
| 共享后端 | `Mem0Memory`（可选） | 向量检索 + LLM 冲突决策 | mem0 REST 远端 |

**4 作用域**（注入时按此顺序层叠合并）：`workspace`（全局约定，仅 admin 写）→ `user`（本人）→ `mission`（单任务）→ `agent`（角色，含两类挂载目标：已发布角色 id `agt_*`、角色值如 `eng`）。

**治理状态机**（bi-temporal，失效不删除）：

```
active ──被取代──▶ superseded（superseded_by 指向新条目，可追溯）
   └──过期──▶ expired
```

- 本地 MemoryStore **永远是数据源**；mem0 只是镜像与决策器，任何远端失败静默降级。
- 默认所有读取只见 `active` 条目；`get(id)` 与 `include_inactive=True` 可读治理态（演变追溯）。

## 2. 写入时机（4 条路径）

| # | 时机 | 触发点 | 行为 | 代码位置 |
|---|---|---|---|---|
| W1 | 人类写入 | 记忆库页 `POST /api/memory` | 落库（走冲突检测）→ 异步 LLM 生成 ≤60 字简介（pending→done/failed，失败降级截断） | `api/app.py` |
| W2 | 任务启动 | `start_pipeline` 锁定 harness 时 | ① Plan-time 检索绑定 top-8 写 `ini.meta`；② `write_memory_pack` 落 `MEMORY_INDEX.md` + `entries/<id>.md` + `usage.log` 进任务目录；③ 写绑定文件 brief/plan/harness | `orchestrator.py`、`mission_memory.py` |
| W3 | stage 执行后 | `executor._run_harness` | ① `record_turn` 会话转录（prompt/reply 各截 2000 字符）；② **角色分层摘要**追加滚动总结（见 2.1）；③ **反思沉淀**（见 2.2）；④ `maybe_summarize` 超预算压缩 | `executor.py` |
| W4 | mem0 镜像 | `CompositeMemory.create` | 仅 `scope="mission"` 条目镜像 mem0（携带 tags/kind metadata），回读其 LLM 冲突决策事件（见 3.2） | `memory.py` |

### 2.1 角色分层摘要（业界：协调器写结论，执行者写增量）

`build_stage_summary()`（`mission_memory.py`）替代旧的「reply 前 600 字符流水账」：

- **协调角色**（`product` / `ops`）：LLM 提炼「决策 / 关键结论 / 遗留风险」要点，最多 5 行；
- **执行角色**（eng/design 等）：降级为增量流水（截断），执行细节本来就在会话转录里；
- LLM 不可用 / `TDT_MEMORY_STAGE_SUMMARY_LLM=false`：全体降级为旧流水，零回归。

### 2.2 反思沉淀（程序性记忆，业界：AgentCore procedural / LangMem 反思）

stage 成功且回复 ≥200 字符时，fire-and-forget 异步 `_reflect_to_memory`：

- LLM 提炼一条同角色可复用经验 → 写入 `scope="agent", scope_id=<角色值>, kind="lesson", tags=["stage:<名>","procedural"]`；
- 后续任务的同类 stage 经 agent 作用域注入链路自动复用（`mission_memory_brief` 的 agent_ids = 角色 id + 角色值）；
- 上限护栏：同 agent 域 lesson 超过 `TDT_MEMORY_REFLECT_AGENT_LESSON_CAP`（默认 20）淘汰最旧（直接 delete，过程性经验无追溯价值）。

## 3. 管理时机（治理，全部零 LLM 或复用 mem0）

| # | 机制 | 时机 | 规则 | 代码位置 |
|---|---|---|---|---|
| M1 | 冲突检测（本地兜底） | 每次条目写入 | 同 scope+scope_id+kind 且分词重合度 ≥ `TDT_MEMORY_CONFLICT_THRESHOLD`(0.8) → 旧条目标记 superseded；**mission 作用域豁免**（并行分支结论相似是常态，交给 M4 仲裁） | `memory.py` `create` |
| M2 | 冲突决策（mem0 主力） | mission 条目镜像时 | mem0 原生 LLM 决策（ADD/UPDATE/DELETE/NOOP）；判定 UPDATE/DELETE → 本地以宽松阈值(≤0.5)跟随标记 superseded，两端演变链一致 | `CompositeMemory.create` |
| M3 | 衰减加权 | 每次检索打分 | `score = 关键词重合度 + 新近度加分`（最近 `TDT_MEMORY_RECENCY_BONUS_DAYS`=3 天内线性衰减加分，最高 +3）——旧记忆沉底不消失 | `memory.py` `_recency_bonus` |
| M4 | 并行分支仲裁 | mission 候选集组装 | 同主题（重合度 ≥ 阈值）多分支：权重 = 人工写入(+2) > 反思沉淀(+1) + 新近度，最高者为采纳，落选者以 `branch:reference` 标签缩进标注「另一分支结论」，信息不丢失 | `memory.py` `merge_stage_conclusions` |
| M5 | 滚动总结压缩 | stage 后 & bootstrap 组包 | `memory.md` 超 `TDT_MISSION_CONTEXT_TOKEN_LIMIT`(60000 token) → LLM 压缩写回，失败降级「保头 + 保最近 4 条」 | `mission_memory.py` |
| M6 | 反思上限淘汰 | 每次反思写入后 | agent 域 lesson 超 cap 淘汰最旧（见 2.2） | `memory.py` `enforce_agent_lesson_cap` |
| M7 | 简介生成状态机 | 人类写入后 | pending → done/failed，failed 可前端重试 | `api/app.py` |

> 治理原则（源自业界共识）：**语义记忆的更新路径比写入路径更重要**；失效用标记不用删除（Zep bi-temporal），冲突禁止后写覆盖（多智能体综述）。

## 4. 读取时机（4 个注入点 + 1 条主动链路）

| # | 时机 | 注入内容 | 检索范围 | 代码位置 |
|---|---|---|---|---|
| R1 | 任务创建（Plan-time） | top-8 简介行 → `ini.meta["memory_brief"]`，ids → `memory_ids` | 四层作用域，query=title+brief；`weknora` 模式走语义召回，`mem0` 后端时命中前置（`CompositeMemory.context_candidates`） | `orchestrator.py` `create_initiative` |
| R2 | stage 执行前（Run-time） | `Layered memory brief` 段 | 四层作用域 + stage 标签隔离 + 分支仲裁 + 衰减排序；agent_ids 含角色 id 与角色值 | `graph.py` → `orchestrator.mission_memory_brief` |
| R3 | harness prompt 拼装 | 滚动总结全文 + 绑定文件（单文件截 6000 字符）+ artifact 索引 + RAG brief | 任务目录文件 + knowledge_gateway | `executor.py` `_build_prompt` |
| R4 | 房间讨论 | 发言者 user 域 + mission 域简介块 | user（发言者，缺省回退创建者）+ mission | `orchestrator.py` 房间回复 |
| R5 | Agent 主动取用 | 读 `MEMORY_INDEX.md` 决定 → 读 `entries/<id>.md` 全文 → `echo id >> usage.log` | 任务目录（workspace 内） | 约定于 `write_memory_pack` 生成的索引头 |
| R6 | stage 执行中（in-loop） | Agent 在回复的 ` ```toolkit_intent ` 围栏声明 `{"memory_search": {"query": ...}}` / `{"memory_read": {"id": "mem_xxx"}}`，编排层（`graph.run_memory_meta`）兑现，结果并入下阶段 brief；读取 ids 记任务 usage.log（面板可见） | 共享记忆库（R6 检索走 R1/R2 同路径） | `graph.py` `run_memory_meta`、`executor.py` `_MEMORY_META_PROTOCOL` |

注入形态统一为**简介行**（`- [kind|id] summary`，总量硬截 6000 字符），全文按需加载——控制上下文预算的同时保留深入路径。

### 4.1 记忆类型 × 存储 × 检索路径对照

「任务执行过程中产生的记忆」与「界面创建的记忆」走**同一条目记忆体系**——落库路径相同（`MemoryStore.create`），差异只在作用域过滤条件：

| 记忆类型 | 来源 | 存储 | 检索方式 |
|---|---|---|---|
| 界面创建条目 | 记忆库页写入 | memory.json（4 作用域） | R1/R2 简介行注入；回映射检索（见下） |
| 反思沉淀经验（程序性） | stage 成功后异步生成 | memory.json，`scope="agent"`、`scope_id=角色值`（如 `eng`） | R2 注入：`agent_ids` 含角色值（`orchestrator.py:108-110`），同角色后续任务召回；WeKnora 镜像在 `memory/agent/<角色>/` |
| 子房间结论 | 并行分支 stage 产出 | memory.json，`scope="mission"`、`scope_id=ini_xxx`、`stage:<名>` 标签 | R2 注入：`stage_applies` 只进所属 stage；分支仲裁（M4）选采纳；WeKnora 镜像在 `memory/mission/<id>/` |
| 滚动总结 memory.md | stage 后自动追加/压缩 | 任务目录 `memory/memory.md` | **全文注入不检索**（R3）；超 token 预算走 LLM 压缩（M5）而非截断召回 |
| 会话转录 sessions/*.jsonl | 每次 harness 执行后追加 | 任务目录 `memory/sessions/` | bootstrap 时取最近 10 轮（`load_session_log(limit_turns=10)`），不检索 |
| 绑定文件 context/*.md | 任务启动写入 | 任务目录 `memory/context/` | 全文注入（R3，单文件截 6000 字符），不检索 |
| stage 产物 | stage 执行产出 | 本地 catalog + WeKnora（`ini:<id>` 标签，folder `missions/<id>`） | `gateway.retrieve`（已是 WeKnora 混合检索 + mission 命名空间隔离，`executor.py:347` `_rag_brief`），受 `TDT_KB_MISSION_INDEX` 开关控制 |

**条目类记忆的 WeKnora 检索回映射**（已实施，`TDT_MEMORY_RETRIEVAL=weknora` 启用，`memory_mirror.py`）：

```
本地 MemoryEntry(id=mem_xxx)
   → 镜像: WeKnora 文档 title="mem:mem_xxx"（folder 按作用域划分）
   → 检索: hybrid_search / graph 命中 → hit.knowledge_title 去掉 "mem:" 前缀
   → 回映射: 本地 get("mem_xxx") → 作用域/治理态/stage 过滤 → 注入简介行
```

id 的权威来源始终是本地 `memory.json`；WeKnora hit 的 knowledge_id/chunk_id 属于知识库文档体系，与记忆条目 id 是两套体系，靠 title 中的 `mem:` 前缀桥接。WeKnora 只负责召回与语义排序；作用域、治理态（superseded 过滤）、stage 隔离、user 隐私这些结构化语义在本地过滤。

## 5. 配置项总表（全部 `TDT_` 前缀）

| 配置 | 默认 | 说明 |
|---|---|---|
| `TDT_MEMORY_BACKEND` | `local` | `mem0` 时启用共享后端镜像与检索合并 |
| `TDT_MEM0_BASE_URL` / `_API_KEY` / `_USER_PREFIX` / `_TIMEOUT` | None/`sortie`/5.0 | mem0 连接 |
| `TDT_MEMORY_STAGE_SUMMARY_LLM` | `true` | 协调角色分层摘要（false 或无 LLM 降级流水） |
| `TDT_MEMORY_REFLECT_ENABLED` | `true` | 反思沉淀开关 |
| `TDT_MEMORY_REFLECT_AGENT_LESSON_CAP` | `20` | agent 域 lesson 上限 |
| `TDT_MEMORY_RECENCY_BONUS_DAYS` | `3.0` | 新近度衰减窗口（天） |
| `TDT_MEMORY_CONFLICT_THRESHOLD` | `0.8` | 本地冲突检测分词重合度阈值 |
| `TDT_MEMORY_RETRIEVAL` | `local` | 条目记忆检索路径：`local`（关键词打分+新近度）\| `weknora`（混合检索+rerank，graph 模式走图谱扩展；失败逐级降级 hybrid → 本地打分） |
| `TDT_WEKNORA_MEMORY_KB_ID` | None | 记忆镜像专用 WeKnora 知识库 id，缺省回落主库 `TDT_WEKNORA_KB_ID` |
| `TDT_MEMORY_TOOLS` | `true` | 内置记忆元工具（memory_search / memory_read，in-loop 声明-兑现） |
| `TDT_MEMORY_READ_BUDGET_PER_STAGE` | `4` | 单阶段 memory_read 预算（含被拒次数，防刷） |
| `TDT_MEMORY_READ_MAX_CHARS` | `2000` | memory_read 返回全文的单条截断 |
| `TDT_MISSION_CONTEXT_TOKEN_LIMIT` | `60000` | 任务上下文包 token 预算（约 4 字符/token） |

## 6. 与业界方案的对应

| 本项目机制 | 业界对应 |
|---|---|
| 4 作用域层叠注入 | Mem0 四层作用域 API / Cursor、Claude Code 层叠规则 |
| 角色分层摘要 | 多智能体记忆综述「协调器写结论、执行者写增量」 |
| 反思沉淀 lesson | AgentCore "procedural" 策略 / LangMem 反思式自我改进 |
| 冲突检测（mem0 LLM 决策 + 本地规则兜底） | Mem0 ADD/UPDATE/DELETE、Azure Foundry Consolidation |
| superseded 失效标记（不删除） | Zep/Graphiti bi-temporal |
| 新近度衰减加权 | Mem0 新近度排序、记忆陈旧化治理 |
| 并行分支权重仲裁 + Provenance | 多智能体综述「禁止后写覆盖，权重/置信度仲裁」 |
| 简介索引 + 全文按需读 | Claude Code MEMORY.md 模式 / Letta 分层分页 |

## 7. 已知边界与后续

- 条目记忆检索已支持 WeKnora 混合检索 + rerank + graph（`TDT_MEMORY_RETRIEVAL=weknora`，默认 `local`）；启用后需执行 `scripts/rebuild_memory_mirror.py` 回填存量条目，新建/更新/删除自动镜像；
- `TDT_MEMORY_BACKEND=mem0` 时 Plan-time / Run-time 候选集自动前置 mem0 检索命中（`CompositeMemory.context_candidates`，按内容互含回映射）；
- 内置记忆元工具已上线（R6）：memory_search / memory_read，预算与隐私护栏见配置表；
- 质量评估脚本 `scripts/memory_eval.py` 已建立（内置 8 用例，`--cases` 可扩展）：**local 关键词打分基线命中率约 38%**——语义检索（weknora）是主要提升方向，启用后重跑对比；
- 文件类记忆（滚动总结 / 转录 / 绑定文件）为全文注入不检索——若后续纳入 WeKnora 按需检索，可复用 knowledge_gateway（同 stage 产物链路）；
- 详见《多Agent协作记忆-调研与实现对照.md》3.2 节。
