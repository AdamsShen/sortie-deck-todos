# Git Worktree 隔离机制说明

> 本文档说明 Sortie Deck 中「每个任务独立的 Git worktree，并发任务互不污染代码库」的实现原理。

## 1. 普通 Git 的痛点

通常一个 Git 仓库只有 **一个** 工作目录 + 一个 `.git`。要切到另一个分支开发，得 `git stash` / `git checkout` 来回切换，多个任务无法同时在同一目录里并行改代码。

## 2. `git worktree` 做了什么

`git worktree add <目录> <分支>` 能让你在 **同一个仓库**（共享同一套 `.git` 对象库、历史、引用）下，**再开一个独立的工作目录**，但：

- 各自 checkout 不同的分支；
- 各自有独立的文件副本；
- 互不干扰——A 目录改的文件不会影响 B 目录。

本质 = 「一份历史数据库 + 多个并行的工作台」。

## 3. Sortie Deck 里怎么用

代码位于 `src/sortie_deck/plugins/coding.py` 的 `ensure_worktree()`：

```python
def ensure_worktree(repo_root: Path, initiative_id: str, worktrees_root: Path) -> Path:
    """Create an isolated work directory (git worktree when possible)."""
    worktrees_root.mkdir(parents=True, exist_ok=True)
    target = worktrees_root / initiative_id          # data/worktrees/<id>
    if target.exists():
        return target

    git_dir = repo_root / ".git"
    if git_dir.exists() and _which("git"):
        branch = f"tdt/{initiative_id}"              # 每个任务一个分支
        subprocess.run(["git", "branch", branch])    # 建分支
        result = subprocess.run(
            ["git", "worktree", "add", str(target), branch]  # 开独立工作台
        )
        if result.returncode == 0:
            return target

    # 兜底：无 git 时退化为纯目录
    target.mkdir(parents=True, exist_ok=True)
    (target / "README.md").write_text(...)
    return target
```

即每来一个任务：

1. 在 `data/worktrees/<id>` 建一个独立目录；
2. 对应建一个 `tdt/<id>` 分支；
3. 把该分支 checkout 到这个目录。

编码 Agent（Claude Code / Cursor）运行时 `cwd` 就指向这个 worktree，它写的代码全落在这个目录、这个分支上。

## 4. 「互不污染」是怎么保证的

- **目录隔离**：任务 A 在 `data/worktrees/ini_aaa`，任务 B 在 `.../ini_bbb`，两拨 Agent 各写各的文件夹，不会互相覆盖。
- **分支隔离**：A 的改动提交到 `tdt/ini_aaa`，B 提交到 `tdt/ini_bbb`，彼此历史不串。
- **共享底层存储**：它们共用主仓库的 `.git`，不重复存历史，开销极小。
- **独立合入**：每个任务分支可独立 review / 提 PR / 合并。

## 5. 兜底策略

如果环境里没有 `git`，`ensure_worktree` 会退化为「纯目录 + README」（非 git），Agent 仍可在该目录自由写文件，只是不再有分支隔离。

## 6. 类比

主仓库是「总档案室」，每个任务的工作树是档案室里单独隔出来的「工位」，工位之间用隔断分开、各有自己的文件柜（分支），但共享同一间档案室的基础设施。
