## 三、根因分析

### 3.1 L1 权限配置漏配

云端 `/data/sortie-deploy/sortie/src/.env` 没有 `TDT_CODING_PERMISSION_MODE`，代码默认 `acceptEdits`（`/Library/git-root/sortie-deck-todos/src/sortie_deck/settings.py:133`）。

Claude Code 的 `acceptEdits` 只自动批准文件编辑与只读命令集；`node --test`、`npm`、`curl` 仍需 allow 规则或审批。无人值守时这些调用直接被拒——这正是 36 条 `blocked` 的来源。

### 3.2 L1 任务级提权在 SDK 路径失效

HITL 批准权限阻断后会注入 `[sortie:coding_permission_mode=bypassPermissions]`，但：

- 解析结果只落在 `StageContext.permissions`（`/Library/git-root/sortie-deck-todos/src/sortie_deck/graph.py:1976` 附近）；
- 旧 CLI 路径会读它并加 `--dangerously-skip-permissions`；
- SDK 路径 `claude_code.py` 直接取全局 `settings.coding_permission_mode`（`/Library/git-root/sortie-deck-todos/src/sortie_deck/harness_providers/claude_code.py:228` 附近）。

所以人工提权对 `harness_stage` 完全无效，这也是「轮 2/轮 3 声明 bypass 仍被拒」的原因。

### 3.3 L2 环境阻塞被当成代码缺陷

`test_report.json` 的 `not_a_code_defect` / `status=blocked` 在仓库里 **0 处解析**；编排层只看模型回复里的 ```qa 块（`_parse_qa_verdict` 只解析 `passed`）。于是「环境阻塞」被等价成「代码没写好」。

### 3.4 L3 无返工上限与熔断

`graph.py` 的 QA 判定失败一律 `handoff_target = on_fail`（三个模板都指向 `eng_implement`），`qa_attempt` 只递增不封顶；自检重入还会把环境阻塞再跑一遍。人每点一次「批准」，就再来一轮。

### 3.5 为什么本地不复现

本地 `.env` 早已配置：

```text
# 2026-11-04：acceptEdits 下 harness 的 Bash（node/npm/curl）必须人工批准，无人值守
# 阶段全部被拒 → qa_verify 三轮无运行证据。人工决策后改为 bypassPermissions 放行。
TDT_CODING_PERMISSION_MODE=bypassPermissions
```

本地实测生效值 `mode=bypassPermissions`，所以命令直接放行。云端部署时没有同步这一项——问题因此只在云端暴露。

## 四、解决方案

### 4.1 分层总览

```text
权限层   统一解析 + 任务级透传 + SDK settings 注入
   ↓
归因层   事后读 selftest_log.json / test_report.json → environment_blocked
   ↓
编排层   环境类失败第 1 轮 stopped；连续同失败 N 次兜底
   ↓
执行层   Bash 沙箱（沙箱内免审批）+ 依赖只装 workspace
   ↓
多 harness 公共档位（claude / dsh / codex）
```

### 4.2 权限统一与透传

- 新增 `permissions.py`：`resolve_permission_mode()`（`/Library/git-root/sortie-deck-todos/src/sortie_deck/permissions.py:47`）按「任务级 override > 全局配置 > `acceptEdits`」解析，只接受白名单值。
- `context_pack` 增加 `permission_mode`（`/Library/git-root/sortie-deck-todos/src/sortie_deck/harness_providers/executor.py:1991`），SDK 消费该值（`claude_code.py:228` 附近）。
- CLI 执行器与 SDK 路径共用同一函数，消除分叉。
- `/api/health` 输出实际生效的 `permission_mode`，漏配可一眼发现。

### 4.3 失败归因（事后判定）

- 新增 `StageFailureKind`（`/Library/git-root/sortie-deck-todos/src/sortie_deck/models.py:434`）：`code_defect / environment_blocked / auth_blocked / unknown`。
- 新增 `classify_stage_failure()`（`/Library/git-root/sortie-deck-todos/src/sortie_deck/harness_providers/executor.py:92`）：
  - provider 标记 `permission_block` / `auth_block` 优先；
  - 否则读 `selftest_log.json`（`status=blocked` / tail 含 `requires approval`）；
  - 再读 `test_report.json`（`verdict.not_a_code_defect=true` 或 `status=blocked`）。
- 只采信 `not_a_code_defect` / `status=blocked`，**不采信** `release_decision=do_not_release`（它也可能是真实代码缺陷）。
- 这是事后判定，不做事前预检跳过任务（参考 SWE-bench 的教训）。

### 4.4 自动暂停与熔断

- 新增守卫 `_apply_environment_block_guard()`（`/Library/git-root/sortie-deck-todos/src/sortie_deck/graph.py:974`），在阶段结果出来、返工/自检/门禁之前执行（调用点 `/Library/git-root/sortie-deck-todos/src/sortie_deck/graph.py:2550`）。
- 环境类失败：第 1 轮即置 `stopped`，写 `kind=error` 事件与 warning 日志，不再打回开发。
- 兜底：同一失败签名连续 `TDT_MAX_CONSECUTIVE_SAME_FAILURE`（默认 3）次自动暂停。
- 自检逻辑跳过环境类失败，避免再重跑一次本阶段。
- 门禁 payload 带 `blocked_reason`，前端优先展示。

### 4.5 Bash 沙箱替代全局 bypass

- 镜像 `runtime-harness` 阶段安装 `bubblewrap` + `socat`（`/Library/git-root/sortie-deck-todos/Dockerfile:86`），并分发 `docker/claude-sandbox.json`（`:90`）。
- 配置核心：`sandbox.enabled` + **`sandbox.autoAllowBashIfSandboxed`**（沙箱内命令免审批）+ `allowUnsandboxedCommands=false`；写只允许 cwd/临时目录，网络默认拒绝、按 `allowedDomains` 放行；`credentials.envVars` 遮蔽 API key。
- 注入方式：`TDT_HARNESS_SETTINGS_FILE` → `ClaudeAgentOptions.settings`（文件不存在自动跳过）。
- 容器前提（Ubuntu 24.04 实测）：宿主持久化 `kernel.apparmor_restrict_unprivileged_userns=0`；worker 仅需 `security_opt: [seccomp=unconfined, apparmor=unconfined]`（`/Library/git-root/sortie-deck-todos/docker-compose.yml:56`）。`SYS_ADMIN` 在非 root 进程下无效且放大攻击面，已移除。
- 预检：`sandbox_preflight()`（`permissions.py:148`）+ worker 首个阶段告警；`/api/health` 输出 `sandbox` 状态（`/Library/git-root/sortie-deck-todos/src/sortie_deck/api/app.py:425`）。

### 4.6 任务级依赖（类似 venv）

- 工具链（node / claude / codex / python）预置在镜像，任务间共享；
- 项目依赖只允许装进 `workspace/node_modules` / `workspace/.venv`，全局 `/usr/local` 写入被沙箱拒绝；
- prompt 明确依赖边界（`executor.py::_build_prompt`，仅编码类阶段）；
- 归档与自审范围排除 `.venv` / `venv` / `dist` / `build` / 缓存目录。

### 4.7 多 harness 兼容

| 能力 | claude_code | dsh | codex |
|---|---|---|---|
| 档位来源 | `permission_mode` | `DSH_PERMISSION_MODE` | `--sandbox` |
| 任务级 override | ✅ | ✅（本次补齐） | ✅（首次进入时定档） |
| 沙箱内免审批 | ✅ `autoAllowBashIfSandboxed` | 依赖 profile | ✅ `--ask-for-approval never` |
| 网络控制 | ✅ `allowedDomains` | ❌ 无（只能靠容器 egress） | ✅ `network_access` |
| 读边界 | ✅ `denyRead` / `credentials` | ❌ 读不受限 | ❌ 只管写 |

公共档位放在 `context_pack["sandbox"]["mode"]`（`read_only / workspace_write / full_access`，`/Library/git-root/sortie-deck-todos/src/sortie_deck/harness_providers/executor.py:1998`），由 `resolve_sandbox_mode()`（`permissions.py:82`）解析，各 provider 自行映射。
